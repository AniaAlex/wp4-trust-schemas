# Errors in the ETSI Forge schemas

Checked against ETSI TS 119 602 V1.1.1 (2025-11). Per Annex A, where a schema conflicts with the text, the text prevails.

## JSON

| Source file | Error level | Source document | Reason why it is an error |
|---|---|---|---|
| [1960201_json_schema/rfcs/rfc7517.json](1960201_json_schema/rfcs/rfc7517.json), `jwk.key_ops` (lines 20–23) | High: valid keys are rejected | IETF RFC 7517 (JSON Web Key), §4.3 | RFC 7517 defines `key_ops` as an **array** of strings ("The "key_ops" (key operations) parameter identifies the operation(s) for which the key is intended to be used … Its value is an array of key operation values"). The schema declares it as a single `string`, so the correct form `"key_ops": ["verify"]` fails validation and the invalid form `"key_ops": "verify"` passes. The schema also does not enforce the RFC rule that duplicate values must not be present (`uniqueItems`). |
| [1960201_json_schema.json](1960201_json_schema/1960201_json_schema.json), definition `LoTE` (lines 4–18) and the root (lines 670–678) | High: valid lists are rejected | TS 119 602, clauses 5 and 6.2 | The schema has no `LoTETag` property, and both `LoTE` and the root have `additionalProperties: false`, so a list cannot carry a tag at all. Clause 5 requires exactly one tag ("There shall be only one occurrence of the first two and last components", L580; component 1 is the tag), and 6.2 defines it. The Forge XSD does have it (as `LOTETag`). |
